# Fanqie Music Strategy

## Goal

Turn the current `fanqie_music` path from a usable upload helper into a more professional music-platform release workflow.

This path should be treated as a longform music release surface, not as a short-video derivative.

This strategy should improve:

- release copywriting
- package semantics
- operator workflow
- metadata readiness
- validation standards

It should keep these constraints:

- local-first
- human-in-the-loop
- traceable
- compatible with the existing primary-platform workflow

## Current State

The current `fanqie_music` path is functional, but it is still derived from the short-video workflow in several important ways.

What already exists:

- `prepare-publish` can create `fanqie_music` jobs
- the package is audio-first rather than video-first
- `music-upload-run` can semi-automate browser form filling
- final submit is still intentionally manual
- publish status can be tracked with job JSON and history

What is still too short-video-oriented:

- the base caption is generated by one shared `build_caption` template
- the final publish text is mostly shared caption text plus platform hashtags
- `#短视频BGM` style language can leak into music-platform-facing copy
- package naming still reads like generic publish assets rather than music-release assets
- metadata is enough for traceability, but not yet rich enough for music-platform operator decisions
- validation checks mostly verify file existence, not release readiness

What must stay true for Fanqie-facing generation:

- songs should feel like complete singles rather than clip-first BGM assets
- intros should stay short and bring in clear vocals quickly
- duration should usually land in the `3:00-4:00` range
- outputs significantly below roughly `2:45` should be treated as suspicious for music-platform release unless there is a deliberate reason

## Gap Summary

To feel professional on Fanqie Music, the system should treat music release as a different publishing surface rather than a caption variant.

That difference is not only about copywriting and packaging.
It also applies to composition shape, intro behavior, and expected listening duration.

The current gaps fall into five areas:

1. copywriting is not music-platform-specific
2. package contents are technically usable but semantically thin
3. operator workflow states are not yet expressive enough for music release preparation
4. metadata does not yet capture a music-release brief
5. verification focuses on asset presence more than submission quality

## Target Workflow

The target Fanqie Music workflow should be:

1. generate song with `distribution_target=music_platform`
2. review song for music-platform suitability, not only generic publishability
3. export approved song with a music-release brief
4. prepare a dedicated `fanqie_music` package
5. run semi-automatic upload assistance
6. stop for operator review before final submit
7. record submit outcome and any platform feedback

Generation assumptions before step 1 should include:

- longform song target, not short-video clip target
- direct vocal entry within roughly the first `2-3` seconds
- full-song pacing with complete sections
- reject or regenerate obviously under-length outputs for release use

## Strategy Areas

### 1. Copywriting

Fanqie Music copy should no longer be a short-video caption with appended tags.

The dedicated copy model should include:

- release title presentation
- one short song description
- one short emotion or scene description
- optional singer or creation note when useful
- restrained tag usage

Copy should avoid:

- short-video hook phrasing
- `#短视频BGM`
- excessive hashtag stacking
- obvious traffic-copy templates that make the song feel like an ad asset

Recommended structure:

```text
《歌名》
一句作品介绍，说明情绪、场景或核心主题。
一句补充说明，强调适合聆听的时刻或作品气质。

#原创歌曲 #情绪流行
```

### 2. Package Semantics

The Fanqie package should be treated as a release package, not just an upload bundle.

The package should continue to include:

- `audio.mp3`
- `cover_publish.png`
- `lyrics_clean.txt`
- `meta.json`
- `publish_text.txt`

It should also grow toward:

- a music-platform-specific release brief file
- a clearer operator note file for upload-time reference
- stronger naming that distinguishes release copy from generic caption copy

## 3. Operator Workflow

The operator workflow should explicitly represent music-release handling.

The current flow is close, but should become clearer:

- `pending`: package created, not checked
- `ready`: assets validated, ready for upload session
- `saved_for_review`: browser assist completed, waiting for operator final review
- `under_review`: submitted and awaiting platform outcome
- `completed` or `failed`

Operator-facing notes should tell the human:

- what fields were auto-filled
- what must still be checked manually
- what evidence files are available in the package

## 4. Metadata Readiness

Current traceability fields are valuable, but Fanqie Music needs a small music-release brief in metadata.

The next metadata layer should include:

- `distribution_target`
- `music_platform_profile`
- `release_summary`
- `audience_scene`
- `emotion_keywords`
- `title_display`
- `copy_style`

This does not need a heavy schema at first.
It does need enough structure that the operator can understand the release intent without opening many raw files.

## 5. Validation Standards

Current validation checks prove that files exist.
Professional validation should also check that the package is appropriate to submit.

Fanqie Music readiness checks should eventually include:

- audio exists and is above minimum size
- audio duration meets music-platform expectations
- intro does not drift into a long instrumental lead-in
- cover exists and is above minimum size
- lyrics exist and are non-empty
- release copy exists and is non-empty
- release copy does not contain banned short-video phrases
- release copy length stays within music-platform limits
- required metadata fields exist
- operator note or release brief exists

## First Implementation Slice

The first implementation slice should prioritize the highest-leverage improvements:

1. split music-platform copy generation from short-video caption generation
2. create a Fanqie-specific publish text builder
3. add a small release brief artifact to exported or prepared packages
4. add lightweight validation for Fanqie copy quality
5. update docs and rehearsal coverage

## Acceptance Criteria

This strategy can be considered implemented enough to move forward when:

- `fanqie_music` no longer uses short-video-style publish copy by default
- generated Fanqie publish text does not include `#短视频BGM`
- Fanqie packages include a music-release-oriented brief or note
- the semi-automatic upload flow still works with the new package shape
- verification covers the Fanqie-specific package and copy outputs
- docs show a professional Fanqie Music operating path distinct from Douyin

## Non-Goals For This Slice

Do not expand this slice into:

- rights-management systems
- royalty workflows
- dashboard UI
- trend analytics
- full catalog management
- major provider rewrites

The priority is to make the current Fanqie Music release path credible and professional, not to build a complete music distribution platform.
